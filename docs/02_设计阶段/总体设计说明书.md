# 总体设计说明书

本文档承接 `01_需求阶段/需求规格说明书.md`，用于创建代码工程、设计接口和安排开发顺序。

## 1. 总体技术路线

系统采用“UniApp App 游客端 + Vue3 管理后台 + Spring Boot 后端 + MySQL 数据库 + Dify 知识库 + 阿里云语音/数字人 + 配置式大模型协议适配器”的集成式路线。

| 模块 | 确定选型 |
|---|---|
| 游客端 | UniApp App，交付 Android 安装包 |
| 管理后台 | Vue3 + Element Plus + ECharts |
| 后端服务 | Spring Boot |
| 数据库 | MySQL |
| 缓存 | Redis，用于 FAQ、会话、热点数据、统计缓存和限流 |
| 文件存储 | 本地文件存储 |
| 知识库平台 | 本地 RAG（MySQL `kb_chunk` + `LocalRagService`，余弦相似度检索，启动时从 `assets/knowledge_raw/` 自动导入） |
| 文本大模型 | 配置 `OpenAI-Compatible` / `Anthropic-Compatible` 协议，配置项为 `baseUrl`、`apiKey`、`modelName` |
| 多模态模型 | 配置 `OpenAI-Compatible` / `Anthropic-Compatible` 协议，用于图片识别、OCR、视觉问答 |
| ASR | 阿里云智能语音交互 ASR，语音转文字 |
| TTS | 阿里云智能语音交互 TTS，文字转语音 |
| 数字人服务 | 阿里云数字人服务，采用实时/流式交互模式，后端返回 `streamUrl`（离线视频生产模式不满足 <5s 延迟，不采用） |
| 部署 | Nginx + Spring Boot Jar + MySQL |

## 5. 后端模块结构

> 📌 本节为概览，**精确包结构以《架构设计说明书》§2.3 为准**（根包 `com.guido.scenicai`，分 `common / integration / module` 三大块，每个业务模块内含 controller/service/service.impl/mapper/entity/dto/vo 七件套）。

```text
backend/src/main/java/com/guido/scenicai/
├── common/             # 全局公共：result / exception / config / interceptor / base / constant / util
├── integration/        # ⭐外部 AI 集成层（唯一对外出口）
│   ├── common/         # AI 客户端抽象 + 重试降级模板 + 配置加载器（读 ai_service_config）
│   ├── dify/           # Dify 知识库客户端
│   ├── llm/            # 文本大模型协议适配器（OpenAI/Anthropic 双协议）
│   ├── vlm/            # 多模态模型协议适配器
│   ├── asr/  tts/      # 阿里云 ASR / TTS 客户端
│   └── avatar/         # 阿里云数字人客户端（实时/流式 streamUrl）
└── module/             # ⭐业务模块（每个模块七件套齐全）
    ├── auth/           # 管理员登录鉴权（Sa-Token admin 账号类型）
    ├── tourist/        # 游客注册/登录/个人中心/历史会话（Sa-Token tourist 账号类型）
    ├── scenic/  spot/  route/     # 景区 / 景点 / 路线管理与推荐
    ├── knowledge/      # 知识库文档、同步状态、测试问答
    ├── chat/           # 文本/语音/多轮会话编排（SSE 流式）
    ├── avatar/         # 数字人播报编排（调 integration.avatar）
    ├── sentiment/      # 实时情绪识别 + 离线分析
    ├── dashboard/      # 数据大屏统计接口
    ├── aiconfig/       # AI 服务配置（对应 ai_service_config 表）
    ├── job/            # 定时任务（每日统计 stat_daily 快照）
    ├── log/            # 登录/操作/AI调用/异常/耗时日志查询
    └── file/           # 文件上传、访问、类型校验
```

## 6. 部署规划

比赛阶段不使用 Docker，部署方式保持解释性、复现性和快速排障能力。

| 部分 | 部署方式 |
|---|---|
| Spring Boot 后端 | 打包成 Jar，通过 `java -jar` 启动 |
| 游客端 UniApp App | 构建 Android 安装包，供评委或演示设备安装 |
| 管理后台 Vue3 | 构建后放到 Nginx |
| MySQL | 普通安装部署 |
| 文件上传目录 | 服务器本地目录 |
| 第三方 AI 服务 | 云服务 API 调用 |

服务器目录结构：

```text
/server/
├── backend/
│   ├── scenic-ai-guide.jar
│   └── application-prod.yml
├── web/
│   └── admin-web/
├── upload/
│   ├── knowledge/
│   ├── image/
│   ├── audio/
│   └── avatar/
└── logs/
    └── scenic-ai-guide.log
```

访问规划：

| 入口 | 路径 |
|---|---|
| 游客端 App | 后端接口地址配置为 `https://域名/api` |
| 管理后台 | `https://域名/admin` |
| 后端接口 | `https://域名/api` |

## 7. 开发顺序

1. 准备官方资料包、测试集和演示数据。
2. 设计数据库表和接口契约。
3. 创建 Spring Boot 后端，完成登录、基础数据、Dify 知识库测试、文本问答。
4. 创建管理后台，完成登录、景区/景点/路线、知识库测试、AI 配置。
5. 创建 UniApp App 游客端，完成首页、文本问答、语音问答、数字人展示。
6. 接入阿里云 ASR、阿里云 TTS、阿里云数字人服务；数字人接入前先完成前置验证（确认实时/流式模式、首音 ≤2s、音画同步），验证不通过转备用方案。
7. 完成数据大屏、感受度报告、日志、演示数据开关。
8. 输出部署手册、总体设计文档、方案 PPT 和演示视频。

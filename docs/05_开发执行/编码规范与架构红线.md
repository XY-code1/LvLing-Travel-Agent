## 1. 后端架构红线（治"没架构 / SQL 写 Controller"）

### 1.1 分层红线（可机器扫描）

| # | ⛔ 红线 | 扫描方式 | 判定 |
|---|---|---|---|
| B-01 | Controller 中禁止出现 SQL 关键字 | 在 `**/controller/**/*.java` 中正则搜索 `\b(select|insert|update|delete)\b`（忽略大小写、排除注释与字符串常量中的自然语言） | 命中即违规 |
| B-02 | Controller 禁止注入或调用 Mapper | 在 controller 包搜索 `Mapper` 类型字段 / 参数 | 命中即违规 |
| B-03 | Controller 禁止直接发起外部 HTTP | 在 controller 包搜索 `RestTemplate`/`WebClient`/`HttpClient`/`OkHttp`/`HttpUtil` | 命中即违规 |
| B-04 | Controller 禁止写业务逻辑 | 人工核验：controller 方法体只允许"参数校验 → 调 Service → 返回 Result"，不允许 `if/for` 业务分支、不允许计算 | 有业务分支即违规 |
| B-05 | ServiceImpl 禁止手拼 SQL 字符串 | 搜索 `"SELECT`/`"select`/字符串拼 SQL | 命中即违规 |
| B-06 | Mapper XML 禁止 `${}` 拼接（防注入） | 在 `**/mapper/**/*.xml` 搜索 `${` | 命中即违规（`ORDER BY` 动态列须用白名单枚举，不得 `${}`） |
| B-07 | 外部 AI 调用必须在 `integration` 层 | ASR/TTS/数字人/大模型/Embedding 的 HTTP 调用只能出现在 `integration` 包 | 出现在其他包即违规 |
| B-08 | 禁止跨层/反向依赖 | Controller 不依赖 Mapper；Mapper 不依赖 Service | 违反即违规 |

### 1.2 文件与方法体积红线（治"上千行大文件"）

| # | ⛔ 红线 | 阈值 | 扫描方式 |
|---|---|---|---|
| B-10 | 单个 `.java` 文件行数上限 | **400 行** | 统计行数，超出即违规 |
| B-11 | 单个方法行数上限 | **80 行** | 超出必须拆分 |
| B-12 | 单个方法参数个数上限 | **5 个** | 超出须封装为对象 |
| B-13 | 圈复杂度（if/for/switch 嵌套） | 单方法 ≤ **10** | 超出须拆分 |
| B-14 | 一个 `.java` 文件只允许一个 public 类 | — | 内部类除外 |

### 1.3 命名与结构红线

| # | ⛔ 红线 | 说明 |
|---|---|---|
| B-20 | 包名、类名严格遵守架构书第 3 章 | Controller 后缀 `Controller`、实现类后缀 `ServiceImpl`、Mapper 后缀 `Mapper` |
| B-21 | 请求体用 `XxxDTO`、响应体用 `XxxVO`、库表实体用 `XxxEntity` | ⛔ 禁止直接把 Entity 返回给前端 |
| B-22 | 所有接口返回统一 `Result<T>` | 见接口契约，禁止裸返回 String/Map |
| B-23 | 所有对外时间字段统一 `yyyy-MM-dd HH:mm:ss` | 禁止返回时间戳数字给前端 |
| B-24 | 常量、枚举集中管理 | 状态码、类型值禁止魔法数字散落，须用枚举或常量类 |

### 1.4 异常与事务红线

| # | ⛔ 红线 | 说明 |
|---|---|---|
| B-30 | 禁止空 catch 吞异常 | ⛔ `catch(Exception e){}` 或只有注释 = 违规；必须记录日志或向上抛 |
| B-31 | 禁止 `e.printStackTrace()` | 必须用 SLF4J 日志（`log.error`） |
| B-32 | 统一全局异常处理 | `@RestControllerAdvice` 兜底，禁止每个 controller 各写各的 |
| B-33 | 写操作必须 `@Transactional` | 涉及多表写入的 ServiceImpl 方法必须加事务 |
| B-34 | 外部 AI 调用必须 try-catch + 降级 | 不允许因第三方失败导致整个请求 500，须按接口契约降级 |

## 2. 前端架构红线（管理后台 admin-web + 游客端 tourist-app 通用）

### 2.1 组件与文件体积红线（治"一个大文件上千行 / 不分模块"）

| # | ⛔ 红线 | 阈值 | 扫描方式 |
|---|---|---|---|
| F-01 | 单个 `.vue` 文件行数上限 | **400 行** | 超出必须拆子组件 |
| F-02 | 单个 `<script setup>` 逻辑行数上限 | **250 行** | 超出须抽 composable（`useXxx.ts`）到 `composables/` |
| F-03 | 单个函数行数上限 | **60 行** | 超出须拆分 |
| F-04 | 一个页面不允许把所有逻辑塞在一个文件 | — | 列表页、表单弹窗、搜索栏须拆成独立组件 |
| F-05 | API 调用禁止散落在组件里 | — | 所有请求必须走 `src/api/*.ts` 封装，组件只 import 调用 |
| F-06 | 禁止在组件内直接 `axios.get/post` | — | 只能用统一封装的 `request` 实例 |

### 2.2 TypeScript 与代码质量红线

| # | ⛔ 红线 | 说明 |
|---|---|---|
| F-10 | 禁止 `any` 兜底 | 接口响应必须定义 TS 类型（对齐接口契约的字段）；确需 `unknown` 也不许 `any` |
| F-11 | 业务文件必须是 `.ts`/`.vue` | ⛔ 禁止新建 `.js` 业务文件 |
| F-12 | 必须过 ESLint + Prettier | 提交前 `pnpm lint` 零 error |
| F-13 | 禁止 `console.log` 残留 | 提交前清理，调试日志走统一封装 |
| F-14 | Element Plus 组件禁止混用其他 UI 库 | 唯一组件库，见架构书 0.2 |
| F-15 | 禁止行内写死接口域名 | baseURL 走环境变量 `.env`，禁止硬编码 `http://localhost:8080` |

### 2.3 UI/UX 强制规范（治"丑陋的 AI 风格 UI"）

> 🎨 **本节是硬性验收项**。评分"行业实用与体验性（20 分）"直接看 UI。Codex 的默认 UI 风格（生硬配色、无间距体系、组件堆砌、审美平庸）**不可接受**。

**F-20 强制使用 UI/UX 技能**
- 执行任何前端页面/组件开发任务时，Codex **必须在该轮任务中显式启用 `UI/UX Pro Max` 技能**，并在任务产出说明里注明"本任务已启用 UI/UX Pro Max 技能"。
- ⚠️ **已知局限（务必知悉）**：该技能**只能约束 UI 观感**，**无法**约束 Codex 的分层、体积、诚实性等其他问题；且因 Codex 存在遗忘/幻觉，该技能**经常不生效**。因此本节额外设定**可验收的硬性 UI 标准（F-21~F-28）**作为兜底，审计方按这些标准逐条核验，**不依赖"技能是否启用"这一自述**。

**F-21 设计令牌（Design Token）强制**
- 颜色、间距、圆角、阴影、字号必须定义为 SCSS 变量 / CSS 变量，集中在 `styles/tokens.scss`。
- ⛔ 禁止在组件里写死 `#409EFF`、`padding:13px` 这类魔法值。扫描方式：`.vue` 中出现十六进制色值或裸像素值（非 token 引用）即违规。

**F-22 间距体系**：统一使用 8px 栅格（4/8/12/16/24/32），禁止随意 `margin:7px`。

**F-23 主题一致**：全站一套主色 + 中性灰阶 + 语义色（成功/警告/危险/信息），景区导览场景要求"文旅 + 科技感"的沉稳配色，⛔ 禁止高饱和大红大绿堆砌。

**F-24 布局规范**：
- 管理后台：固定"顶栏 + 侧边导航 + 内容区"经典后台布局，内容区留白充足，表格/表单不贴边。
- 数据大屏：深色科技风，1920×1080 无滚动条铺满，图表有主次层级。
- 游客端：移动端单列流式布局，数字人区域为视觉主体，操作按钮触达友好（点击区 ≥ 44px）。

**F-25 状态完备**：每个数据页面必须处理 4 态——加载中（骨架屏/loading）、空数据（空状态插画/文案）、错误（友好提示 + 重试）、正常。⛔ 禁止只做正常态。

**F-26 反馈明确**：所有异步操作有 loading，成功/失败有 toast，危险操作有二次确认弹窗。

**F-27 响应式**：管理后台适配 1280~1920 宽度不错位；游客端适配主流手机屏。

**F-28 可访问性基线**：文字与背景对比度达标（正文 ≥ 4.5:1），可点击元素有 hover/active 反馈，表单有 label。

> 📌 审计方核验 UI 时，逐条对照 F-21~F-28 打勾，**任一未达标该前端任务判为不通过**，回炉重做，不接受"技能已启用所以算达标"的辩解。

## 4. ⛔ 反"假装完成/说谎/幻觉"行为红线（重点治 Codex）

> 🚨 本节是**诚信红线**。以下行为一经审计发现，该任务**直接判定造假、全部回炉**，并在进度表标注。

| # | ⛔ 严禁行为 | 判定依据 |
|---|---|---|
| H-01 | **谎称完成**：口头说"已实现/已完成"但代码里没有对应实现 | 审计方只认代码与运行证据，不认自述 |
| H-02 | **空实现/占位**：方法体写 `return null` / `// TODO` / 抛 `NotImplemented` 却标记完成 | 全局扫 `TODO`/`FIXME`/空方法体 |
| H-03 | **假数据冒充真实现**：接口返回写死的 mock 数据冒充真实业务逻辑（演示数据开关除外，且必须走 `demo_switch` 表且明确标注） | 检查是否真连库、真调外部服务 |
| H-04 | **注释造假**：注释/文档写"调用了 XX 服务"，实际没有调用 | 对照 `sys_log` 是否有真实调用记录 |
| H-05 | **绕过验证**：把测试改成永远通过、删除断言、`catch` 吞异常假装成功 | 检查 try-catch 是否吞异常、测试是否有真实断言 |
| H-06 | **幻觉 API**：调用了架构书/契约里不存在的库函数、表字段、接口路径 | 对照三份契约文档 |
| H-07 | **偷偷改契约**：擅自修改表结构、接口出入参、目录结构来"绕过"报错 | 对照冻结版文档做 diff |
| H-08 | **虚报测试**：声称"测试通过"但无测试代码或无法复现 | 要求提供可复现的运行命令与输出 |
| H-09 | **遗忘上下文后乱编**：换会话后不读文档就凭记忆瞎写 | 见 Codex 执行约束协议——每轮必须先读文档 |

> ✅ **正确做法**：遇到文档未覆盖、无法实现、依赖缺失、契约冲突等任何"卡点"，**必须停下来在产出里明确写出"我卡在哪、缺什么、需要什么决策"**，而不是编一个假的糊弄过去。**诚实报告卡点=合格；假装完成=造假**。

## 5. 可机器扫描红线汇总（审计脚本据此逐条判定）

> 本表供审计方写扫描脚本/正则逐条核验。命中即违规。

| 编号 | 扫描目标（正则/规则） | 判定 |
|---|---|---|
| S-01 | Controller 类文件中匹配 `(?i)(select\|insert\|update\|delete)\s` | 违规：SQL 进 Controller |
| S-02 | Controller 中匹配 `Mapper` 注入 或 `RestTemplate\|WebClient\|HttpClient` | 违规：跨层/外部调用 |
| S-03 | 任意 `.java` 文件行数 > 400 | 违规：大文件 |
| S-04 | 任意 Java 方法行数 > 80 | 违规：大方法 |
| S-05 | 任意 `.vue` 文件行数 > 400 | 违规：大组件 |
| S-06 | `.vue`/`.ts` 中匹配 `: any` 或 `as any` | 违规：any 兜底 |
| S-07 | 代码中匹配 `sk-[A-Za-z0-9]{10,}` 等疑似明文密钥、或硬编码 `http(s)://` 业务域名 | 违规：硬编码密钥/地址 |
| S-08 | 全局匹配 `TODO\|FIXME\|NotImplemented\|throw new UnsupportedOperation` | 违规：占位/空实现 |
| S-09 | `catch` 块为空 或 仅 `e.printStackTrace()` 无处理 | 违规：吞异常 |
| S-10 | 新建的表名/字段名/接口路径 ∉ 冻结版文档清单 | 违规：幻觉/私改契约 |
| S-11 | 存在 `.js` 业务文件（非配置） | 违规：未用 TS |
| S-12 | `console.log` / `System.out.println` 残留在业务代码 | 违规：调试残留 |

> ⛔ 以上任一命中，对应任务在审计中标记为**不通过**，必须修复后重新提交审计。

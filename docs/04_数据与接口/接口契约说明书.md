> **版本**：V1.0（接口契约基线，冻结版）
>
> - **赛题**：第十五届"中国软件杯"大赛 A 组 · A5 - 景区导览服务 AI 数字人

> - **强制原则**：执行方（Codex）**只能实现本文档列出的接口**。⛔ 严禁瞎编接口路径、⛔ 严禁改字段名、⛔ 严禁增删返回字段。前端调用与后端实现必须与本契约**逐字一致**。若发现缺接口，**必须停止并回问**，不得自行发挥。

## 0. 通用约定（全接口强制遵守）

### 0.1 路径前缀（冻结）

| 端 | 路径前缀 | 鉴权 |
|---|---|---|
| 游客端 | `/api/tourist/**` | Sa-Token 游客登录态（账号类型 `tourist`）；注册/登录接口除外 |
| 管理端 | `/api/admin/**` | Sa-Token 管理员登录态（账号类型 `admin`） |
| 文件访问 | `/files/**` | 匿名可读（仅限上传目录） |
| 接口文档 | `/doc.html`（Knife4j） | 仅开发环境开放 |

> ⛔ **红线**：游客端与管理端用 Sa-Token **多账号体系**隔离（`StpAdminUtil` / `StpTouristUtil`），token 互不通用；管理端接口游客态无法访问，反之亦然。

### 0.2 统一响应包装 `Result<T>`（唯一格式，禁止裸返回）

> ⛔ **红线**：所有 Controller 返回值**必须**包在 `Result<T>` 中，禁止直接返回实体、List、String、Map。

```json
{
  "code": 200,
  "msg": "success",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务状态码，见 0.3 |
| `msg` | string | 提示信息，成功固定 `success` |
| `data` | T | 业务数据，无数据时为 `null` |

### 0.3 业务状态码表（冻结）

| code | 含义 | 触发场景 |
|---|---|---|
| 200 | 成功 | 正常返回 |
| 400 | 参数错误 | `@Valid` 校验失败 |
| 401 | 未登录/令牌失效 | 管理端未登录、游客令牌失效 |
| 403 | 无权限 | 越权访问 |
| 404 | 资源不存在 | 查询 ID 不存在 |
| 429 | 请求过于频繁 | 触发限流（游客端） |
| 500 | 服务器内部错误 | 未捕获异常 |
| 1001 | 外部 AI 服务调用失败 | Dify/大模型/ASR/TTS/数字人异常 |
| 1002 | AI 服务未配置或未启用 | 对应 `service_type` 无 `enabled=1` 记录 |
| 1003 | 知识库未命中（兜底） | RAG 未命中，返回兜底话术 |

### 0.4 分页请求与响应（统一格式）

**分页请求**（所有列表接口，query 参数）：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `pageNum` | int | 否 | 1 | 页码，从 1 开始 |
| `pageSize` | int | 否 | 10 | 每页条数，最大 100 |

**分页响应** `data` 结构（`PageResult<T>`）：

```json
{
  "total": 100,
  "pageNum": 1,
  "pageSize": 10,
  "list": []
}
```

### 0.5 全局字段规范

| 项 | 规则 |
|---|---|
| 时间字段 | 一律字符串 `yyyy-MM-dd HH:mm:ss`（后端 Jackson 全局格式化） |
| 布尔字段 | 一律 `0/1` 整数，禁止 `true/false` |
| ID 字段 | 一律 `number`（后端 bigint，⛔ 序列化为字符串防精度丢失，前端按字符串处理） |
| 枚举字段 | 用文档约定的英文大写常量（如 `TEXT`/`VOICE`/`IMAGE`） |
| 空值 | 无值返回 `null`，禁止返回 `"undefined"`/`""` 混用 |

### 0.6 鉴权头（冻结 · Sa-Token 多账号体系）

> 游客与管理员都用 Sa-Token，但属于**两套隔离的账号体系**（Sa-Token multi-account：`admin` / `tourist`），互不越权。两端登录后都用同一个请求头携带各自 token。

| 端 | 请求头 | 值 | Sa-Token 账号类型 |
|---|---|---|---|
| 管理端 | `satoken` | 管理员登录返回的 token | `admin`（`StpAdminUtil`） |
| 游客端 | `satoken` | 游客登录返回的 token | `tourist`（`StpTouristUtil`） |

> 🧭 **给外行的解释**：游客和管理员各有各的登录，系统内部用两条独立"账号线"区分，游客的 token 打不开管理后台，管理员的 token 也不会被当成游客——即使用同一个请求头名字也不会串。
>
> ⛔ **红线**：API Key 等敏感信息**永远不出现在任何接口返回中**。`ai_service_config` 相关接口返回时凭证字段必须按数据库设计 §4.1 红线脱敏（`api_key`/`access_key_id` 脱敏，`access_key_secret` 仅返回 `hasSecret`）。

## 1. 游客端接口（`/api/tourist/**`）

> 游客 = **注册用户**。除注册/登录外，所有游客端接口都需携带 Sa-Token 游客登录态（请求头 `satoken`，账号类型 `tourist`），未登录返回 `code=401`。所有接口受限流保护（见需求 NF-SEC5）。

### 1.1 游客账号：注册 / 登录 / 资料

| 接口 | 方法 | 鉴权 | 用途 | 关键出入参 |
|---|---|---|---|---|
| `/api/tourist/auth/register` | POST | 免登录 | 手机号注册 | 入：`phone`,`password`,`nickname?`；出：`{ touristId }` |
| `/api/tourist/auth/login` | POST | 免登录 | 登录 | 入：`phone`,`password`；出：`{ token, touristInfo }` |
| `/api/tourist/auth/logout` | POST | 游客态 | 退出 | 出：`null` |
| `/api/tourist/user/profile` | GET | 游客态 | 我的资料 | 出：`{ id, phone, nickname, avatar, gender, interestTags }`（⛔ 无 password） |
| `/api/tourist/user/profile` | PUT | 游客态 | 改资料/兴趣偏好 | 入：`nickname?`,`avatar?`,`gender?`,`interestTags?` |

- **`POST /api/tourist/auth/login` 请求体**：

```json
{ "phone": "13800000000", "password": "明文密码（HTTPS 传输）" }
```

- **响应 `data`**：

```json
{
  "token": "sa-token-xxxx",
  "touristInfo": { "id": 10, "phone": "138****0000", "nickname": "小明", "interestTags": "历史,自然" }
}
```

> ⛔ 登录失败统一返回 `code=400, msg="账号或密码错误"`，禁止区分"手机号不存在/密码错误"（防枚举）。手机号在返回中脱敏中间 4 位。

### 1.2 `POST /api/tourist/session/create` 创建导览会话

- **用途**：游客登录后进入某景区，创建一次导览会话。
- **鉴权**：游客登录态
- **请求体**：

```json
{ "scenicId": 1 }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scenicId` | number | 是 | 进入的景区 ID |

- **响应 `data`**：

```json
{
  "sessionNo": "uuid-xxxx",
  "scenicId": 1,
  "welcomeText": "你好，我是你的专属导游…",
  "defaultAvatar": { "name": "小锐", "avatarImage": "/files/avatar/1.png", "voice": "zhixiaobai" }
}
```

### 1.3 `GET /api/tourist/session/history` 我的历史对话

- **用途**：登录游客查看自己的历史会话列表（对应 `chat_session.tourist_user_id`）。
- **鉴权**：游客登录态
- **响应 `data`**：会话数组 `[{ sessionNo, scenicId, title, lastTime, messageCount }]`；点击某会话可用 `GET /api/tourist/session/{sessionNo}/messages` 拉取该会话消息。

### 1.2 `POST /api/tourist/chat/text` 文本问答（★ 核心）

- **用途**：游客发送文本问题，返回 AI 回答 + 数字人流地址。
- **鉴权**：游客登录态
- ⚠️ **传输方式**：本接口**实际以 SSE 流式返回**（见 §3.1 `/api/tourist/chat/text/stream`），此处的"响应 data"仅用于**说明最终聚合后的字段语义**，供前端拼装和落库对照。⛔ 禁止实现成"整段生成完再一次性返回 JSON"。
- **请求体**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionNo` | string | 是 | 会话编号 |
| `question` | string | 是 | 问题文本，1~500 字 |
| `spotId` | number | 否 | 当前所在/所问景点，用于上下文 |

- **响应 `data`**：

```json
{
  "messageId": 123,
  "answer": "灵山大佛始建于…",
  "hitKb": 1,
  "sources": [ { "docName": "灵山景区讲解词.pdf", "spotName": "灵山大佛" } ],
  "emotion": "NEUTRAL",
  "streamUrl": "https://avatar.aliyun.../stream/xxx",
  "audioUrl": "/files/audio/xxx.mp3",
  "costMs": 3200
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `messageId` | number | 消息 ID |
| `answer` | string | AI 回答文本（用于气泡展示） |
| `hitKb` | number | 是否命中知识库 1/0；0 时 `answer` 为兜底话术 |
| `sources` | array | 引用来源，未命中为 `[]` |
| `emotion` | string | 识别到的游客情绪 |
| `streamUrl` | string | 数字人流地址，前端播放；降级时为 `null` |
| `audioUrl` | string | TTS 音频，数字人降级时用 |
| `costMs` | number | 端到端耗时（毫秒） |

> ⛔ 前端**只播放** `streamUrl`；`streamUrl` 为 `null` 时降级播 `audioUrl` + 静态形象。禁止前端自行调用任何 AI 服务。

### 1.3 `POST /api/tourist/chat/voice` 语音问答（★ 核心）

- **用途**：游客上传录音，后端 ASR → RAG → LLM → TTS → 数字人。
- **鉴权**：游客登录态（Sa-Token `tourist`）
- **传输**：同 1.2，实际以 SSE 流式为准（见 §3.2），本节仅定义字段语义。
- **请求体**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionNo` | string | 是 | 会话编号 |
| `audio` | file | 是 | 录音文件，格式 wav/mp3/pcm，≤60s，≤5MB |
| `spotId` | number | 否 | 上下文景点 |

- **响应 `data`**：在 1.2 基础上**多一个** `asrText` 字段：

```json
{
  "messageId": 124,
  "asrText": "灵山大佛有多高",
  "answer": "灵山大佛高 88 米…",
  "hitKb": 1,
  "sources": [],
  "emotion": "NEUTRAL",
  "streamUrl": "https://…",
  "audioUrl": "/files/audio/xxx.mp3",
  "costMs": 4100
}
```

### 1.4 `POST /api/tourist/vision/recognize` 拍照识别景点（★ 核心）

- **用途**：游客上传景点图片，多模态模型识别 → 映射景点 → 讲解。
- **鉴权**：游客登录态（Sa-Token `tourist`）
- **请求体**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionNo` | string | 是 | 会话编号 |
| `image` | file | 是 | 图片，jpg/png，≤10MB |

- **响应 `data`**：

```json
{
  "messageId": 125,
  "recognizedSpot": { "spotId": 3, "spotName": "九龙灌浴", "confidence": 0.92 },
  "answer": "这是九龙灌浴，讲述的是…",
  "streamUrl": "https://…",
  "audioUrl": "/files/audio/xxx.mp3",
  "costMs": 3800
}
```

> `recognizedSpot` 为 `null` 表示未识别出景点，`answer` 返回引导话术。

### 1.5 `GET /api/tourist/route/recommend` 个性化路线推荐

- **用途**：按兴趣返回匹配路线；登录游客未传 `interest` 时，默认取 `tourist_user.interest_tags` 作为兴趣来源（对齐个性化，需求 T-04）。
- **鉴权**：游客登录态（Sa-Token `tourist`）
- **query 参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scenicId` | number | 是 | 景区 ID |
| `interest` | string | 否 | 兴趣关键词（历史/自然/亲子/摄影…） |
| `routeType` | number | 否 | 路线类型枚举，见数据库 `route.type` |

- **响应 `data`**：路线数组

```json
[
  {
    "routeId": 1,
    "name": "历史文化深度游",
    "type": 4,
    "estimateMinutes": 180,
    "recommendReason": "适合对历史感兴趣的游客",
    "spots": [ { "spotId": 1, "name": "灵山大佛", "sortOrder": 1 } ]
  }
]
```

### 1.6 `GET /api/tourist/spot/{id}` 景点详情（含讲解入口）

- **鉴权**：游客登录态（Sa-Token `tourist`）
- **响应 `data`**：`spot` 表核心字段 + 是否可讲解标记。

### 1.7 `GET /api/tourist/scenic/hot` 首页热门景点 / 推荐问题

- **鉴权**：游客登录态（Sa-Token `tourist`）
- **响应 `data`**：

```json
{
  "hotSpots": [ { "spotId": 1, "name": "灵山大佛", "coverImage": "/files/image/1.jpg" } ],
  "recommendQuestions": [ "灵山大佛有多高？", "景区有哪些必去景点？" ]
}
```

### 1.8 `POST /api/tourist/feedback/submit` 游客反馈

- **鉴权**：游客登录态（Sa-Token `tourist`）
- **请求体**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sessionNo` | string | 否 | 关联会话 |
| `score` | number | 否 | 1~5 |
| `content` | string | 否 | 文字反馈 |

- **响应 `data`**：`null`（`code=200` 即成功）

### 1.9 `GET /api/tourist/spot/nearby` GPS 附近景点推荐

- **用途**：P6-T04 GPS 弱信号闭环的第一段，按游客当前位置推荐附近可用景点；GPS 不可用时游客端降级到拍照定位和手动选点。
- **鉴权**：游客登录态（Sa-Token `tourist`）
- **query 参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scenicId` | number | 是 | 景区 ID |
| `longitude` | number | 是 | 当前经度 |
| `latitude` | number | 是 | 当前纬度 |

- **响应 `data`**：附近景点数组，按距离从近到远排序，最多返回 8 条。

```json
[
  {
    "spotId": 1,
    "name": "灵山大佛",
    "distanceMeters": 128,
    "coverImage": "/files/image/1.jpg",
    "canGuide": true
  }
]
```

## 2. 管理端接口（`/api/admin/**`）

> 管理端接口**全部**需要 `Authorization: Bearer <token>`（Sa-Token 签发）。未登录返回 `code=401`。列表接口统一分页。

### 2.0 统一分页约定

- **列表请求 query**：`pageNum`（默认 1）、`pageSize`（默认 10）+ 各自筛选字段。
- **列表响应 `data`**：

```json
{ "total": 100, "pageNum": 1, "pageSize": 10, "list": [ /* 记录数组 */ ] }
```

### 2.1 登录鉴权

| 接口 | 方法 | 用途 | 关键出入参 |
|---|---|---|---|
| `/api/admin/login` | POST | 登录 | 入：`username`,`password`；出：`{ token, adminInfo }` |
| `/api/admin/logout` | POST | 退出 | 出：`null` |
| `/api/admin/info` | GET | 当前登录信息 | 出：`{ id, username, realName, role }` |

> ⛔ 登录失败返回 `code=400, msg="账号或密码错误"`，⛔ 禁止提示"用户不存在/密码错误"区分（防枚举）。

### 2.2 景区 / 景点 / 路线管理（标准 CRUD）

> 三者均为标准 CRUD，接口形态一致，以景点为例，其余同构。

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/admin/spot/page` | GET | 分页查询（筛选：`scenicId`,`name`,`tag`,`status`,`isHot`） |
| `/api/admin/spot/{id}` | GET | 详情 |
| `/api/admin/spot` | POST | 新增（body 为 spot 字段） |
| `/api/admin/spot` | PUT | 修改 |
| `/api/admin/spot/{id}` | DELETE | 逻辑删除 |
| `/api/admin/spot/status` | PUT | 启停：`{ id, status }` |

> 景区 `/api/admin/scenic/**`、路线 `/api/admin/route/**` 同构。路线额外含 `/api/admin/route/spots`（PUT，配置路线景点顺序：`{ routeId, spotIds: [3,1,2] }`）。

### 2.3 知识库管理（★ 评分关键）

| 接口 | 方法 | 用途 | 关键出入参 |
|---|---|---|---|
| `/api/admin/knowledge/page` | GET | 文档分页（筛选 `scenicId`,`syncStatus`） | 出：文档列表含 `syncStatus` |
| `/api/admin/knowledge/upload` | POST | 上传文档（multipart：`file`,`scenicId`） | 出：`{ docId, syncStatus }` |
| `/api/admin/knowledge/sync/{id}` | POST | 手动触发同步到 Dify | 出：`{ syncStatus, syncMsg }` |
| `/api/admin/knowledge/{id}` | DELETE | 删除文档（同时删 Dify 侧） | 出：`null` |
| `/api/admin/knowledge/status` | PUT | 启停文档 | 入：`{ id, status }` |
| `/api/admin/knowledge/test` | POST | ★ 知识库测试 | 见下 |

- **`POST /api/admin/knowledge/test` 请求体**：`{ "question": "灵山大佛有多高？" }`
- **响应 `data`**：

```json
{
  "answer": "灵山大佛高 88 米…",
  "hit": 1,
  "sources": [ { "docName": "讲解词.pdf", "segment": "…原文片段…", "score": 0.87 } ],
  "costMs": 900
}
```

### 2.4 AI 服务配置（★ 含密钥安全）

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/admin/ai-config/list` | GET | 按 `serviceType` 查配置列表 |
| `/api/admin/ai-config` | POST/PUT | 新增/修改配置 |
| `/api/admin/ai-config/{id}` | DELETE | 删除 |
| `/api/admin/ai-config/enable` | PUT | 启用某配置为默认：`{ id }` |
| `/api/admin/ai-config/test/{id}` | POST | 连通性/能力校验（VISION 须传测试图片） |

- **请求体字段**（对齐数据库 `ai_service_config` 表 §4.1 全字段）：`serviceType`,`provider`,`protocol`,`baseUrl`,`apiKey`,`accessKeyId`,`accessKeySecret`,`appKey`,`region`,`modelName`,`datasetId`,`extraConfig`,`timeoutMs`,`retryCount`,`enabled`,`remark`。
- **前端表单动态渲染**：后台按 `serviceType` 只显示数据库 §4.1.1「必填字段矩阵」中该类型标 ✅/⭕ 的字段。例如选 `ASR/TTS/AVATAR` 显示阿里云三件套（`accessKeyId`/`accessKeySecret`/`appKey`/`region`），选 `LLM/VISION/KB` 显示 `apiKey`/`baseUrl`。
- **`GET /api/admin/ai-config/list` 响应**：凭证字段按数据库 §4.1 红线返回：
  - `apiKey`、`accessKeyId` → 脱敏为 `****1234`（保留后 4 位）；
  - `accessKeySecret` → **不返回任何值**，仅返回布尔 `hasSecret`（`true`=已配置）；
  - 其余非敏感字段正常返回。
- **新增/修改规则**：新增时传全量凭证；修改时凭证字段**传空字符串 = 保持原值不变**，传新值 = 覆盖（避免脱敏值被回写成密文）。
- **`POST /api/admin/ai-config/test/{id}` 校验接口**：真实调用一次对应服务，返回 `{ success, costMs, msg, capabilityVerified }`；`VISION` 类型须随请求传一张测试图片，验证多模态图片输入能力，通过才置 `capabilityVerified=1`。
- ⛔ **安全红线**：任何响应、任何日志中**禁止**出现 `accessKeySecret` 明文或脱敏值；数据库存储所有凭证字段 AES 加密（对齐数据库 §4.1）。

## 3. 流式接口规范（★ 保障 <5s 首响应体感）

> ⛔ **红线**：语音问答、文本问答的答案生成**必须走 SSE 流式**，禁止"整段生成完再一次性返回"。这是延迟达标（需求 NF-PERF）的硬性手段，审计方会核对是否真流式。

### 3.1 文本问答流式接口

- **`POST /api/tourist/chat/text/stream`**，响应 `Content-Type: text/event-stream`。
- **事件序列**（按顺序推送）：

```
event: meta        data: {"sessionNo":"xxx","messageId":123}
event: delta       data: {"text":"灵山"}          // LLM 逐块吐字，多条
event: delta       data: {"text":"大佛高88米"}
event: sources     data: {"hit":1,"sources":[...]}  // 命中的知识库来源
event: emotion     data: {"emotion":"NEUTRAL"}
event: audio       data: {"audioUrl":"/files/audio/xx.mp3"}   // TTS 完成
event: avatar      data: {"streamUrl":"https://.../stream"}   // 数字人流地址
event: done        data: {"costMs":3200,"success":true}
```

- **前端渲染规则**：收到 `delta` 即刻上屏（打字机效果），收到 `avatar` 即开始播放数字人流，`done` 后落库。

### 3.2 语音问答流式接口

- **`POST /api/tourist/chat/voice/stream`**（multipart 上传音频后转 SSE），事件序列在 3.1 基础上**前置**：

```
event: asr         data: {"text":"灵山大佛有多高"}   // ASR 识别结果先回，供前端显示纠错
```

其余事件同 3.1；其中 `done` 事件额外携带语音链路阶段耗时：

```json
{
  "costMs": 4200,
  "success": true,
  "asrMs": 650,
  "retrieveMs": 120,
  "llmMs": 1800,
  "ttsMs": 900,
  "avatarMs": 700
}
```

### 3.3 数字人口型契约（对齐需求 E-05）

> 固定为阿里云数字人**实时/流式模式**。后端 `avatar` 事件只下发 `streamUrl`，前端播放即得音画同步（口型/表情由服务端合成）。

- **降级契约**：若数字人服务失败，`avatar` 事件改为 `{"streamUrl":null,"fallback":"AUDIO","audioUrl":"..."}`，前端退化为"静态形象 + 纯语音播放"，⛔ 不得中断整轮对话（对应 R-06）。

## 4. 统一错误码表（冻结）

> ⛔ Codex 必须使用下列错误码，禁止自造 code。所有异常经全局异常处理器 `@RestControllerAdvice` 统一包装。

| code | 含义 | 场景 |
|---|---|---|
| 200 | 成功 | 正常 |
| 400 | 参数错误 | 校验不通过、业务参数非法 |
| 401 | 未登录/Token 失效 | 管理端未带或过期 Token |
| 403 | 无权限 | 越权访问 |
| 404 | 资源不存在 | 查无此 ID |
| 429 | 请求过于频繁 | 触发游客端限流 |
| 500 | 服务器内部错误 | 未捕获异常 |
| 1001 | 外部 AI 服务超时 | Dify/LLM/ASR/TTS/数字人超时 |
| 1002 | 外部 AI 服务返回错误 | 第三方返回非成功 |
| 1003 | 知识库未命中（业务提示，非错误） | RAG 低于阈值，走兜底 |
| 1004 | 文件类型/大小不合法 | 上传校验失败 |
| 1005 | AI 配置缺失或未启用 | 未配置默认 LLM/数字人等 |

> `code=1001/1002` 时，`msg` 须含服务商与场景（脱敏），并已落 `sys_log`（`log_type` 对应）。

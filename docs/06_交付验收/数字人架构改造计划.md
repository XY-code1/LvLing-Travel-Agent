# 数字人（虚拟形象）架构改造计划

> 写于 2026-07-07，基于当前代码库探测结果

---

## 一、当前架构探测总结

### 1.1 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Java 21 + Spring Boot + MyBatis-Plus |
| 管理后台 | Vue 3 + Element Plus + Vite |
| 游客端 | uni-app（Vue 3 + Vite，H5 发行） |
| 数据库 | MySQL，`schema.sql` 位于 `database/` |

### 1.2 AI 服务集成架构（已存在）

```
ai_service_config 表              (LLM / VISION / ASR / TTS / EMBEDDING / AVATAR)
         │
         ▼
   AiConfigLoader.loadDefault(ServiceType)
         │
         ▼
   AiConfigSnapshot ──→ 按 protocol 路由:
                           LLM     → OpenAiCompatibleAdapter / AnthropicCompatibleAdapter
                           VISION  → OpenAiCompatibleVlmAdapter / AnthropicCompatibleVlmAdapter
                           ASR     → AliyunSpeechClient.recognize()
                           TTS     → AliyunSpeechClient.synthesize()
                           AVATAR  → AliyunAvatarClient.createStream()
```

当前各服务都经过 `AiConfigLoader` 抽象，**ASR/TTS/LLM/VLM 已经协议化**，不绑定阿里云（可在管理后台配置切换）。

**唯一绑定阿里云的是数字人形象（AVATAR 服务类型）**——`AliyunAvatarClient.createStream()` 调用阿里云智能媒体服务，返回一个视频流 URL，前端 `<video>` 标签播放。

### 1.3 游客语音对话链路（ASR→LLM→TTS→Avatar）

```
录音 ─→ TouristVoiceStreamService
         ├── ① AliyunSpeechClient.recognize()        ASR → 文字
         ├── ② LocalRagService.retrieve()            知识库检索
         ├── ③ LlmClientRouter.stream()              LLM 流式回答
         ├── ④ AliyunSpeechClient.synthesize()       TTS → audioUrl
         ├── ⑤ AliyunAvatarClient.createStream()     数字人视频流 → streamUrl
         └── ⑥ SSE 推送:
                delta(文字) + audio(audioUrl) + avatar(streamUrl) → App
```

### 1.4 图片识别链路（VLM→知识库）

```
拍照 ─→ TouristVisionController
         ├── ① storeImage()                  保存图片
         ├── ② VlmClientRouter.recognize()   多模态模型 → 识别文字
         ├── ③ localKnowledgeService
         │       .findByRecognizedText()      只做了关键词匹配 ★ 此处缺失完整推理
         ├── ④ tryTts()                      如果命中就 TTS
         └── ⑤ tryAvatar()                   如果命中就数字人视频流
```

**问题**：VLM 输出的文字没有进入 RAG + LLM 流程。目前只是拿识别结果去知识库做关键词匹配，没有让文本大模型基于"知识库上下文+识别结果"做完整推理回答。

### 1.5 数字人配置表

当前 `avatar_config` 表字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint | 主键 |
| name | varchar | 形象名称 |
| provider | varchar | 服务商（默认"阿里云数字人"）|
| instance_id | varchar | 阿里云实例 ID |
| avatar_image | varchar | 形象图 URL |
| voice | varchar | 音色 |
| speech_rate | int | 语速 |
| welcome_text | varchar | 欢迎语 |
| is_default / enabled | tinyint | 默认 / 启用 |

**缺失字段（你要求的"外观、服装"）：**
- 服装/装扮配置
- 外观描述或预设选择
- 渲染参数（口型区域、动画参数）

### 1.6 前端渲染现状

`tourist-app/components/AvatarBox/index.vue`：

```vue
<video v-if="streamUrl" :src="streamUrl" autoplay />
<view v-else>
  <!-- fallback: 纯文字状态 -->
</view>
```

**完全依赖阿里云返回的视频流**，没有阿里云 streamUrl 时只展示纯文字占位。

## 二、你要的架构（确认）

```
游客App录音
       │
       ▼ 后端
   ① ASR（可配置，不绑阿里云）
       │
       ▼
   ② 知识库 RAG 检索
       │
       ▼
   ③ 文本大模型 LLM（可配置）
       │
       ▼
   ④ TTS（可配置，不绑阿里云）
       │
  ┌────┴──────────┐
  │                │
  ▼                ▼
  audioUrl         answer 文字
  │                │
  ▼                ▼
  ⑤ App Canvas 渲染 ←── 播放音频 + 根据文字/时间驱动口型
```

**图片处理路径**：
```
游客拍照
       │
       ▼
  VLM（可配置，只负责看图片，输出文字）
       │
       ▼
  ② ③ ④ → 进入文本大模型流程（与语音答案走同一条知识库+LLM 管线）
```

**关键变化**：
- **去掉 `AliyunAvatarClient.createStream()`**（数字人视频流）
- **App 本地 Canvas 渲染形象图**，TTS 音频播放时驱动口型动画
- **VLM 输出喂给 LLM（RAG 上下文 + VLM 文字 → 完整答案）**

## 三、改动范围与工作量

### Phase 1：后端 — 改造图片识别链路 `2-3h`

**目标**：VLM 识别结果进入 RAG+LLM 完整管线，而不是只做关键词匹配。

| 文件 | 改动 |
|---|---|
| `TouristChatServiceImpl.java` `recognizeImage()` | 把 VLM 识别文字作为 question，走 `retrieveContext()` + `buildAnswer()` 完整流程 |
| 删除代码 | `tryAvatar()` 不再调用 Aliyun，直接返回 `null` |
| `TouristTextStreamService.java` | 去掉 `AliyunAvatarClient` 依赖，`tryAvatar()` 返回 `null` |
| `TouristVoiceStreamService.java` | 同上 |

### Phase 2：后端 — 数字人配置扩展 `1-2h`

**目标**：avatar_config 表增加外观/服装字段，供 Canvas 渲染使用。

| 文件 | 改动 |
|---|---|
| `database/schema.sql` | 新增 `outfit`、`outfit_image`、`render_config` 字段 |
| `AvatarConfig.java`（entity） | 新增字段 |
| `AvatarConfigVO.java` | 同步新增 |
| `AvatarSaveDTO.java` | 同步新增 |
| `AvatarConfigServiceImpl.java` `copyFields()` / `toVO()` | 同步 |
| `AvatarConfigService.java` | 新增 `getDefaultWithDetail()`（含外观信息） |
| admin 前端 `AvatarManage.vue` | 表单增加"服装/装扮"选项 |
| admin 前端 `types/index.ts` | 同步类型 |

### Phase 3：后端 — 开放游客端 Avatar 配置接口 `0.5h`

**目标**：游客 App 启动/进入会话时获取当前默认数字人的完整配置（形象图、服装、音色、欢迎语、口型参数等）。

| 文件 | 改动 |
|---|---|
| 新增 `AvatarConfigController.java` `GET /api/tourist/avatar/default` | 返回当前启用数字人的完整配置 |
| `ChatSessionServiceImpl.java` | 返回的 `defaultAvatar` 包含外观字段 |

### Phase 4：前端 — Canvas 数字人渲染组件 `4-6h`

**目标**：替换 `<video>` 为 Canvas 本地渲染，播放音频时驱动口型。

| 文件 | 改动 |
|---|---|
| `AvatarBox/index.vue` | 重写：Canvas 画形象图 + 口型驱动 |
| `AvatarBox/avatar-canvas.ts`（新建） | Canvas 渲染逻辑（画人、口型动画、呼吸效果） |
| `AvatarBox/types.ts`（新建） | AvatarRenderConfig 类型定义 |
| `chat/index.vue` | 接入新的 AvatarBox |
| `vision/index.vue` | 同 |

**渲染方案（2 选 1）**：
| 方案 | 复杂度 | 效果 | 推荐 |
|---|---|---|---|
| **A. 简单的开合口型** | 低 | 播放音频时椭圆蒙版循环缩放 | ⭐ 当前阶段推荐 |
| **B. 基于音频振幅 + 帧动画** | 中 | Web Audio AnalyserNode 提取音量驱动口型帧 | 可作为后续优化 |

**方案 A 实现思路**：
1. Canvas 绘制形象图（支持上衣/身体分层叠加）
2. 音频播放时，在 mouth 区域叠加一个随时间变化的椭圆（周期 200ms 左右开合）
3. 音频结束时口型恢复闭合
4. 可选：每 4-6s 一次轻微呼吸（身体微微上下）

外部效果：配合 `welcomeText` 展示文字气泡 + 情绪标签。

### Phase 5：管理后台 — 外观配置表单 `1.5h`

**目标**：后台数字人编辑页面增加服装、外观预览、渲染参数配置。

| 文件 | 改动 |

## 五、依赖与注意事项

1. **不再调用阿里云数字人**：`AliyunAvatarClient.java` 可保留（不倒删，里面日志能力还有用），但 chat 服务中不再调用其 `createStream()` 方法。
2. **ASR/TTS 不变**：还是走 `ai_service_config` 配置，可以在后台切换为其他供应商。
3. **Canvas 跨平台**：uni-app H5 的 Canvas 2D API 可用，未来编译到微信小程序等需适配。当前 H5 先用标准 Canvas。
4. **口型同步精度**：方案 A 是视觉近似同步（非音素级）。要精准需要后端返回音素时间戳（phoneme timing），当前阶段过度设计了。可先上线方案 A。
5. **avatar_config 不改动已有字段**：只新增 `outfit` / `outfit_image` / `render_config`（JSON 文本列），不影响现有数据。

## 六、实施结果（2026-07-07 已落地）

### 6.1 已完成的架构切换

当前运行链路已经改为：

```
游客 App 录音
       │
       ▼
后端 ASR → 知识库 RAG → 文本 LLM → TTS
       │                         │
       │                         ├── answer 文字
       │                         └── audioUrl 音频
       ▼
游客 App Canvas 数字人渲染：播放 audioUrl，并按文字/时间驱动口型
```

图片链路已经改为：

```
游客拍照 → VLM 看图输出文字 → RAG 检索 → 文本 LLM 生成讲解 → TTS → Canvas 数字人播放
```

VLM 只负责“看图转文字”，不会直接作为最终回答；最终讲解统一由知识库上下文 + 文本大模型生成。

### 6.2 后端完成项

- 已移除聊天主链路对 `AliyunAvatarClient.createStream()` 的依赖，不再生成阿里云数字人视频流。
- 文本问答、语音问答、图片识别返回 `audioUrl + answer`，`streamUrl` 保留为兼容字段但返回 `null`。
- `avatar_config` 已扩展 `gender`、`appearance`、`outfit`、`outfit_image`、`render_config` 字段。
- 游客端接口已支持：
  - `GET /api/tourist/avatar/list`：返回已启用、可供游客选择的数字人形象
  - `GET /api/tourist/avatar/current`：返回当前游客选择的数字人
  - `PUT /api/tourist/avatar/current`：保存游客自己的数字人选择
  - `GET /api/tourist/avatar/default`：兼容旧调用，返回当前游客选择
- `POST /api/tourist/session/create` 支持传入 `avatarId`，并将本次会话使用的数字人固化到 `chat_session.avatar_config_id`。
- TTS 已按会话数字人的 `voice/speech_rate` 输出音频；女性形象默认 `xiaoyun`，男性形象默认 `xiaogang`，后端会拦截明显性别不匹配的音色。
- `ai_service_config` 后台可配置类型中已去掉 `AVATAR`，只保留 ASR/TTS 等真实仍需配置的 AI 服务。

### 6.3 管理后台完成项

- 新增“数字人形象管理”菜单，替代原“数字人服务”配置入口。
- 数字人形象库固定，不开放新增、编辑、删除。
- 管理员只负责启用/停用形象；启用后的形象才会出现在游客端选择列表。
- 测试播报已改为生成并播放 TTS 音频，不再依赖 `streamUrl`。

### 6.4 游客端完成项

- `AvatarBox` 已从 `<video>` 改为 Canvas 渲染。
- 个人中心已支持游客选择自己的数字人形象。
- 聊天页已支持直接切换数字人；切换后会开启新会话，保证形象和音色同步。
- Canvas 渲染支持：
  - 默认数字人形象图加载
  - 上半身裁剪展示
  - 轻微呼吸动画
  - 播放音频时口型开合
  - 根据回答文字和播放进度生成近似口型节奏
- 聊天页、拍照识别页和路线拍照定位入口均已接入游客当前选择的数字人配置。

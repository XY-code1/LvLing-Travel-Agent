# 旅灵（TravelLing AI）产品愿景

## 1. 产品定位

旅灵是面向多城市旅行场景的 AI 旅行定制数字人员工平台。它不是普通旅游内容站，也不是单一聊天机器人，而是以城市为上下文、以数字人为统一入口、以结构化旅行服务为结果的旅行服务系统。

核心闭环：

```text
选择/搜索城市
  → City Context 切换
  → 首页内容、景点、服务、公告、知识库和 AI 上下文同步切换
  → AI 旅行数字员工理解意图
  → 查询资料、生成讲解、规划行程、处理服务和求助
```

第一版以 Web/H5 为主，不实现 GPS 实时定位和实时导航。当前灵山视觉仅作为沉浸式体验基线，不直接决定最终 UI 重构方案。

## 2. 体验原则

1. 城市是第一上下文：切换城市必须改变内容数据和 AI Context，而不只是修改标题。
2. 数字人是全局入口：首页、景点、路线、服务和 SOS 均可进入同一 AI 工作流。
3. 结果结构化：路线输出为 Journey 数据，而不是不可编辑的大段文本。
4. 数据优先：Database → RAG → External API → Web Search，联网能力按需启用。
5. 渐进迁移：保留 Guido 的稳定接口和表，先兼容，再迁移，再淘汰旧路径。
6. 可运营：城市内容、POI、设施、公告、知识源、数字人配置均可由后台维护。

## 3. 游客端一级模块

- 首页：城市视觉、热门 POI、天气摘要、公告、快捷问答和数字人。
- AI 导览：多轮旅行问答、景点讲解、上下文连续对话。
- 景点：按城市、区域、分类筛选，支持详情、讲解、提问和加入行程。
- 路线规划：结构化表单和自然语言两种入口，输出可编辑 Journey。
- 服务查询：城市/区域下的卫生间、餐厅、停车、医务等设施。
- 公告：城市、景区和服务相关公告。
- SOS 求助：整理求助信息，提供 110/120/122、旅游热线和景区服务信息。
- 个人中心：用户资料、历史行程、对话和反馈。

## 4. 多城市目标

杭州和西安只是示例城市。城市切换应统一驱动：

- 首页背景、文案和推荐内容；
- 景区、POI、路线、服务设施和公告；
- RAG 检索范围与知识来源；
- AI 的 City Context、Journey Context 和推荐策略；
- 数字人欢迎语、语音和运营配置。

## 5. Guido 能力的产品化保留

保留现有 backend、admin-web、MySQL、Redis、Sa-Token、RAG、ASR/TTS、Avatar、景点/路线/服务/公告/SOS 等能力。Phase 2 的重点是建立领域边界和迁移路径，不是一次性重写实现。

## 6. Phase 2 成功标准

- 形成稳定的 City Context 数据契约。
- 明确旧 `scenic/spot/route` 到新领域模型的兼容关系。
- 形成 TravelProfile、Journey 和 Agent Tool 的可实现契约。
- 迁移可回滚，不破坏 Phase 1 的管理员登录、游客登录和现有接口。
- 完成后可进入 Phase 3 的第一个垂直闭环：城市切换 + POI 查询 + 结构化行程草案。
